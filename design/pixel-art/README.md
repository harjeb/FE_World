# 像素素材

状态：UI 设计稿用的原型素材由 [`gen_art.py`](gen_art.py) 用代码逐像素画出，全部原创，没有使用火焰纹章的角色、标志或美术资产。运行时交战动画已另行接入 FE-Repo 素材，转换结果和实际署名见 [`fe-anims/`](fe-anims/README.md)，原始匹配方案见 [`fe-repo-candidates/`](fe-repo-candidates/README.md)。

[UI 设计画板](https://claude.ai/artifact/27oMCYU8APZE8R1ukpj2qn)里的图就是这些 PNG 的上传副本。画板默认只有所有者能打开，要给别人看，需在页面的分享菜单里开启。

![素材总览（4 倍）](contact.png)

## 重新生成

只用素材的话什么都不用装，PNG 已经在 `png/` 里。修改或新增素材需要 Python 3 和 Pillow（本次在 Python 3.11.2、Pillow 9.4.0 验证）。

在项目根目录运行：

```bash
# 覆盖 design/pixel-art/png/ 和两张总览图
python3 design/pixel-art/gen_art.py

# 输出到其他目录，再和现有文件比较
python3 design/pixel-art/gen_art.py /tmp/pixel-art
diff -r design/pixel-art/png /tmp/pixel-art/png
```

唯一的参数是输出根目录，省略时为脚本所在目录。素材写入 `<根目录>/png/`，总览图 `contact.png`（4 倍）和 `contact_maps.png`（2 倍）写入根目录。

所有随机取值都用固定种子，每次运行的像素完全相同；Pillow 版本相同时，文件也逐字节相同。仓库里的 PNG 用 Pillow 9.4.0 生成；换别的版本（例如 12.1.1）重新生成，像素不变，但每个文件的字节都会变，`diff -r` 会全部报不同。

## 显示规则

- PNG 都是 1 倍原图。放大只用整数倍，并设置 `image-rendering: pixelated`，否则像素会被插值模糊或宽窄不一。
- 画板中的用法：地图和地图单位多为 3 倍（一格 48 px），头像 2–3 倍，图标和纹章多为 2 倍，交战演出 4 倍。小地图是缩小显示，不受整数倍限制。

## 游戏里绘制的交战形象

交战演出里的人物按**职业**逐个设计：77 个在用职业各一张 48×48 侧视形象（面朝右，显示时 4 倍），代码在 `backend/common/sprites/`：

- `looks/<路线>.ts` 写着每个职业的设计：用哪些手绘部件、摆在哪里、配什么颜色，外加只属于它自己的细节（头饰、上衣、披风、坐骑等）。头部、站姿和坐骑是共用的手绘部件，只为让各职业比例一致，不做随机组合。
- 骑乘、飞行等职业画坐骑（`looks/mounts.ts`）：马、披甲马、鳞甲马、飞鸵、天马、飞龙、战车。
- 换色：己方蓝、敌方红（阵营色部件）；肤色、发色取角色头像（固定人物见 `character-colors.ts`，随机角色取随机头像），所以战斗里认得出是谁。职业专属的颜色不随阵营变。
- 手里的武器单独一层（`WEAPON_LAYERS`），按这次交战用的武器类型画在职业声明的手部位置；施放法术时画一本书。
- `poses.ts` 从现有分层形象生成待机两帧、准备、出手、收招、受击和闪避。手臂绕肩部活动，武器跟随握点；剑斧短刀挥砍、枪拳爪前击、弓拉弦、书杖龙石抬手施放。坐骑图层保持完整，头饰与头部同步，脚底固定。
- `battle.test.ts` 校验每职业、武器和姿势的完整性、确定性、握持连接、画布边界与配色；默认待机帧保留原图。
- 前端 `frontend/src/assets.ts` 的 `battleSpriteFor` 按人物配色、实际武器、姿势和帧缓存 data URL（最多 256 张）；已停用的旧职业退回路线小人。
- `frontend/src/battle/combat-motion.ts` 只安排演出时间：HP、命中、反击、追击和反噬均来自服务端逐击记录。远程攻击显示飞行物，必杀延长准备与命中停顿；支持跳过和系统的减少动态效果设置。

## 游戏里生成的头像

没有手绘头像的单位（通用敌兵，以后的随机招募角色）由游戏现场生成头像，代码在 `backend/common/portraits/`：

- `draw.ts` 是本脚本头像部分的 TypeScript 移植，部件、坐标和配色完全相同。`portraits.test.ts` 读取本脚本的 `PORTRAITS`，用 TS 重画每个角色，要求和 `png/por_*.png` 逐像素一致。所以改脸型、发型、服装、配饰或五官时，两边要一起改，否则测试失败。
- `random.ts` 按种子随机组合部件。先定性别，再抽肤色、发色、瞳色、脸型、发型、五官、胡子、伤疤和眼镜；服装、布料颜色和头饰按职业路线和阵营抽，敌方布料偏红和暗色。每个部件都固定抽一次随机数，所以同一单位换职业或阵营时脸不变，只换衣服和头饰。头盔和兜帽会换成对应的发型；女性不长胡子，蒙面时也不画胡子。
- 前端 `frontend/src/assets.ts` 的 `portraitFor` 给没有手绘头像的单位生成头像：用单位 id 当种子，服装取它的职业路线，画好后缓存成 data URL。遭遇战的敌兵 id 是 `e0`、`e1`……，所以每场同一位置的敌兵长得一样；要每场不同，可以让后端给生成的单位存一个头像种子。

## 与随机地图生成器的关系

两边使用同一张地形表，字符和地形种类都一致；[随机地图生成器](../../docs/10-random-map-generator.md)的 SVG 预览配色也取自这里的色板。`tools/mapgen` 的测试会读取本脚本的 `PAINTERS`，字符对不上时测试失败。

这里的示例地图仍是为设计稿手写的布局。游戏里其他地图（随机生成、任务、地下城、经典关卡）由前端现场绘制，见下一节。

## 游戏里绘制的地图

上表「画板里的名字」那几张地图直接用 PNG，其余地图由游戏现场绘制，代码在 `backend/common/maps/draw.ts`：

- `draw.ts` 是本脚本地形部分的 TypeScript 移植，画法、配色和随机取值完全相同，连 Python 的随机数生成器也一并移植了。`draw.test.ts` 读取本脚本的 `MAPS`，用 TS 重画每张地图，要求和 `png/map_*.png` 逐像素一致。所以改地形画法时，两边要一起改，否则测试失败。
- 桥默认按东西向通行来画。桥的东西两侧（越过相连的桥格）都是水，而南北两侧不都是水时，改画成南北向。本脚本的示例地图都是东西向过河，生成器的地图两个方向都有。
- 前端 `frontend/src/assets.ts` 的 `mapArt` 给没有 PNG 的地图现场绘制：用地图名算种子，所以同一张图每次进入、回放时都一样；画好后缓存成 data URL。每格用自己的随机数，所以战斗中某格地形改变（墙被打破变成地板）时，只有这一格和相邻格的边缘会变。
