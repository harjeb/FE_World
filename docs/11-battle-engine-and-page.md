# 11 战斗引擎与战斗页

状态：引擎在前端与服务端共用，页面已接入服务端（docs/07）：出击、竞技场进攻、防守、养成操作都通过 op 提交，日期按个人日历（docs/00 §2）显示。下面「页面现状」列出各页的真实内容与剩余缺口，完整缺口清单见 docs/12。

## 运行

需要 Node.js 22.18+。

```bash
cd frontend
npm install
npm run dev            # http://localhost:8524 ，端口可用 WEB_PORT 修改
npm run build          # 产物在 frontend/dist
npm run typecheck

# 引擎与竞技场单元测试（在项目根目录运行）
node --test backend/common/engine/*.test.ts backend/common/arena/*.test.ts

# 浏览器整局测试，需要本机有 Chromium（CHROME_BIN 可指定）
npm run test:e2e
```

地址后加 `?seed=任意文字` 可以固定随机种子，同一种子加同样的操作一定得到同一局。

## 结构

按 [07 技术架构](07-architecture.md)：规则只写一份，放在 `backend/common`，前端直接打包这份源码。以后服务端、Agent 查询接口和模拟器也用同一份代码。

| 位置 | 内容 |
| --- | --- |
| `backend/common/data/` | 职业、武器、角色、技能数据表，数值取自 02、03 |
| `backend/common/engine/` | 确定性战斗引擎：`step(state, action) → { state, events }`；可达范围、交战预测、威胁区等只读查询；规则 AI |
| `backend/common/battles/pinepass.ts` | 示例关卡「黑松隘口」：地图布局与像素素材 `map_pinepass` 一致（有测试核对），单位数值是示例数据 |
| `frontend/src/battle/` | 战斗页：控制器、事件播放、地图、侧栏、交战演出、对话框 |
| `frontend/src/arena/` | 竞技场：今日结果、禁用、部署、进攻、防守设置 |
| `frontend/src/pages/`、`frontend/src/watch/` | 演示页面：军营、名册、转职；Agent 观战、历史回放（见下文「演示页面」） |
| `frontend/src/demo/` | 演示页面用的示例数据（赛季时间、资源、名册状态、进阶职业、防守结果、奖励） |
| `frontend/test/battle-replay.e2e.mjs` | 用规则 AI 规划整局行动，在无头 Chromium 中点击重放，核对胜负与 Node 预测一致；另有王城压制、防守设置、演示页面、观战与回放几个场景 |

引擎不读时钟，也不用 `Math.random`。随机数用 xoshiro128\*\*，状态保存在战斗状态里；战斗判定和升级成长分成两条随机流。所以「初始状态 + 指令序列」可以完整重现一局，浏览器测试就是靠这一点逐局核对的。

## 已实现的规则

- **移动**：按 03 的地形消耗和四类移动方式计算；敌方单位阻挡通行；友军可以穿过，但不能停在友军所在格。
- **交战**：
  - 攻速、攻击力、伤害、命中、回避、必杀均按 03 的公式。
  - 武器三角、特效 ×3、勇者武器连击、攻速差 4 追击。
  - 飞行单位不享受地形加成。
  - 射程不够时无法反击。
- **判定**：命中取两个随机数的平均值（2RN），必杀取一个随机数。交战预测里的击败概率按这种真实判定逐一枚举计算，界面上显示的命中、必杀仍是规则数值。
- **行动**：攻击、治疗（杖）、伤药、压制、待机，与移动一起原子提交。
  - 压制：只有我方主将、只能在压制地图的王座上执行，执行后立即获胜。
  - 攻击后该武器成为装备武器，之后用它反击。
  - 所有单位行动完后自动结束阶段。
  - 撤退立即判负。
- **经验与成长**：
  - 交战、击败、击败首领、用杖的经验按 03 计算。
  - 升级用纯随机成长，带空级保护（最多重掷 2 次），受职业能力上限约束。
- **地形与胜负**：
  - 站在堡垒、王座上的单位，在所属一方的阶段开始时回复 20% 最大 HP。
  - 胜负条件：击败敌方主将、全歼敌军、压制王座、我方全部退出、回合用尽；压制地图上全歼不算胜利，我方主将被击败即判负。
- **技能**：12 个样例角色的个人技能都已生效，并计入交战预测和治疗预览。
- **规则 AI**：
  - 进攻、伺机、固守、护卫、治疗优先五种行为。
  - 攻击目标按「期望伤害 + 击败概率 × 50 − 期望反击伤害」打分选择，结果是确定的。

## 为实现先定下的暂定规则

以下几项在设计文档里还没有定，引擎先按下面的方式实现。改起来都只涉及一处代码：

| 事项 | 当前做法 | 位置 |
| --- | --- | --- |
| 村庄 | 移动消耗同平地，回避 +10，拜访效果未做 | `maps/map.ts`、03 地形表 |
| 单位 HP 归零 | 统一显示为「被击败，退出战斗」。09 草案的永久死亡、不朽盾和石化尚未接入 | `engine/resolve.ts` |
| 固守 | 原地不动，只反击。示例关卡的主将用这种行为 | `engine/ai.ts` |
| 回合上限 | 第 20 回合敌方阶段结束仍未获胜即判负（竞技场规则），野外关卡是否设上限待定 | `engine/step.ts` |
| 庇护（诺亚） | 被治疗单位在本回合（含敌方阶段）防 +2 | `engine/skills.ts` |
| 经验与等级 | 按 02、03 的旧规则：基础职业 Lv20 封顶。09 草案改为 99 级后需要重算 | `engine/growth.ts` |
| 压制地图的胜负 | 只有压制王座算胜利，全歼守军也要再压制；我方主将被击败即判负 | `engine/step.ts` |
| 规则 AI 的进攻方主将（压制地图） | 王座在移动范围内就压制；否则只打被反杀概率 ≤ 5% 的仗；守军剩 2 人以下才向王座推进，此前原地待命 | `engine/ai.ts` |

## 战斗页

按 08 的「选中单位并预览攻击」设计稿实现。

- **布局**：地图约占 70%，战术栏约 30%，一屏显示，地图和战术栏各自滚动；宽度不足 1100px 时上下排列。
- **操作流程**：选单位 → 预览落点（显示路线）→ 选择行动、武器、目标 → 查看预测 → 确认执行。
  - 在移动范围内直接点敌人，会自动选好站位并打开交战预测。
  - Enter 确认，Esc 逐步返回。
  - 方向键移动光标，空格选择，整个流程都可以只用键盘完成。
- **地图**：
  - 显示可移动（蓝）、攻击范围（红斜纹）、治疗范围（绿斜纹）、敌方威胁区（点状纹理加虚线外沿，T 键开关）、网格（G 键开关）、拟定路线、预览落点和目标标签。标签会避开单位，不遮挡单位。
  - 支持 2× / 3× 整数倍缩放、拖动平移，小地图可以点击跳转。
  - 已行动单位去色并打 ✓，敌方主将带小旗。
  - 压制地图：王座有金色虚线框，选中我方主将或鼠标停在王座上时显示「王座 · 压制目标」；主将的落点在王座上时，行动栏出现「压制」，其他人站上去会提示只有主将能压制。
- **交战演出**：侧视画面，逐击显示伤害和 HP 变化，可跳过。可以选择全部播放、仅主将战或关闭；关闭时伤害数字直接显示在地图上。
- **其他画面**：升级弹窗（逐项显示属性提升）、结束阶段确认（列出未行动的人）、撤退确认、胜负结算（含三星条件）、战况记录。
- **资源**：像素素材直接取自 `design/pixel-art/png`。像素字体 Silkscreen 打包在项目里，中文使用系统字体，页面不请求任何外部资源。

## 竞技场进攻流程

按 05 实现：竞技场首页（今日 3 个对手）→ 查看对手并禁用 B 人（名单按等级排序，不暴露优先级、站位和 AI）→ 揭晓实际出战的 D 人、站位和对方对我的预设禁用 → 选 D 人、指定主将、在出生区摆位（可点击或方向键）→ 进攻方先手开战（不给经验，可投降）→ 按 05 计分（胜 +20、无阵亡 +5、半数回合内获胜 +5）。

- 规则在 `backend/common/arena/`：`maps.ts`（平原会战 6+2、山间隘口 5+1、林中遭遇 4+2、王城 8+3，布局即像素地图）、`rules.ts`（禁用后按优先级取前 D 人、主将被禁用时由备选顶上、编成校验、生成战斗、计分）、`demo.ts`（我方 12 人快照名册与 3 个对手的防守设置，属性按等级取成长期望值）。
- 3 个对手：霜狼骑团（平原会战）、赤枫商会（山间隘口）、白塔学士团（王城，11 人名单）。林中遭遇只出现在防守设置的地图选项里。
- 王城 20×14：护城河上一座桥、两处浅滩，三道城门，王座在大厅最里面 `(18,7)`。禁用页地图放不下 2 倍时改用 1 倍显示，不做非整数缩放。
- 进攻进度存在浏览器本地（`agent-tactics.arena-day`，对手数据变化时会作废旧进度），暂离或刷新后可继续；首页有「重置今日进攻（演示用）」。
- 规则 AI 互打的进攻胜率（每个对手 60 局，轮流禁用、轮换出战人员）：霜狼骑团约 17%、赤枫商会约 45%、白塔学士团（王城）约 35%。名册从 8 人扩到 12 人后，轮换会派出等级较低的新角色，所以前两个对手的数字比 8 人名册时（约 30%、58%）低。

## 竞技场防守设置

`#/arena/defense`，从竞技场首页的「修改防守设置」进入。今日竞技场继续使用第 6 月末快照里的防守；这里改的是下一次（第 7 月末锁定）的防守，保存在浏览器本地（`agent-tactics.defense-next`），暂代 SET_DEFENSE。

- 选择防守地图：名单人数（D + B）、出生区和禁用名额随地图变化。换图时按优先级保留单位，主将站王座或堡垒（都没有就站防守区中间），其余人由近到远围在主将周围；人数不够时提示补人（王城要 11 人）。
- 防守名单：
  - 用 ↑ / ↓ 调整优先级，排在 D 名之后的是替补；
  - 为每个人选择 AI 行为，治疗优先只给会用杖的单位；
  - 点格子或按方向键调整站位，遇到己方单位交换位置；
  - 可以移出名单或从名册补人。
- 地图标出每个单位的优先级、行为和主将 / 备选角标，并画出选中单位的行为范围：伺机的触发范围、固守的反击范围、护卫在主将 3 格内的活动范围、治疗范围。
- 主将顺序（主将 + 最多 2 名备选）与预设禁用（最多 B 个角色名）。
- 校验错误（人数、站位、主将、禁用）会阻止保存。主将排在出战人数之外等不合理设置，只给提示、不阻止保存。顶部显示未保存的修改数，可放弃修改。
- 「用陪练 AI 试攻」：规则 AI 用 3 个对手的名册各进攻 4 次，先禁用等级最高的单位，统计守住几次。规则在 `backend/common/arena/defense.ts`。

## 页面现状

所有页面读写服务端数据（GET_STATE / GET_TODAY / GET_ARENA / GET_DEFENSE / GET_ROSTER 等）；顶栏显示个人日期与下个事件（竞技场日）。

| 页面 | 地址 | 真实内容 | 仍是演示或待做 |
| --- | --- | --- | --- |
| 军营 | `#/camp`（首页） | 个人日期与季进度、待办（进行中的战斗、今日或下一个竞技场日、上次结果）、行动（耗日、金币与推进到的日期来自 GET_TODAY）、重要日期、Agent 上报的计划 | 军团概况里的主力 / 重伤（G06） |
| 出击 | `#/field` | 出征准备：地区敌方等级与讨伐状态、队伍（上限取 GET_TODAY）、胜利条件、回合上限、推进日期与阵亡风险；确认后才 SORTIE，未完的野外战斗会续上 | — |
| 名册 | `#/roster/<id>`、`/growth` | 属性与成长率（含类型 / 年龄修正）、装备（TRANSFER_ITEM）、历次升级（含野外战斗升级）、竞技场快照对比（GET_SNAPSHOTS） | 主力 / 替补 / 重伤状态（G06） |
| 转职 | `#/roster/<id>/promote` | 五阶职业的相邻转职（PROMOTE），成长率按当前职业修正 | 解锁规则待定，开发版无门槛 |
| 竞技场 | `#/arena` | 竞技场日的 3 场进攻（禁用 → 部署 → 战斗）；结算后的防守试攻、积分、勋章与金币；他人公开的回放 | 排名按积分估算 |
| 防守设置 | `#/arena/defense` | GET / SET_DEFENSE，报名锁定状态（`locked` / `lockedDay`） | — |
| 观战 / 回放 | `#/spectate`、`#/replay` | 服务端回放（GET_REPLAYS / GET_REPLAY）：播放、单步、倍速与跳转 | 观战实为最近一场回放（G10） |

- 回放把引擎一次结算的敌方阶段按单位拆成步骤，每一步的局面由事件重建，与引擎终局逐项一致（单位位置、HP、存活、等级、属性）。
- 整备、规则手册、设置还没有页面，导航入口点了会提示。
