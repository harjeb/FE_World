# 11 战斗引擎与战斗页

状态：引擎在前端与服务端共用，页面已接入服务端（docs/07）：出击、竞技场进攻、任务、整备与养成操作都通过 op 提交，日期按个人日历（docs/00 §2）显示。下面「页面现状」列出各页的真实内容与剩余缺口，完整缺口清单见 docs/12。

## 运行

需要 Node.js 22.18+。

```bash
cd frontend
npm install
npm run dev            # http://localhost:8524 ，端口可用 WEB_PORT 修改
npm run build          # 产物在 frontend/dist
npm run typecheck

# 引擎与竞技场单元测试（在项目根目录运行）
node --test backend/common/engine/*.test.ts backend/common/arena/*.test.ts

# 浏览器整局测试，需要本机有 Chromium（CHROME_BIN 可指定）
npm run test:e2e
```

地址后加 `?seed=任意文字` 可以固定随机种子，同一种子加同样的操作一定得到同一局。

## 结构

按 [07 技术架构](07-architecture.md)：规则只写一份，放在 `backend/common`，前端直接打包这份源码。以后服务端、Agent 查询接口和模拟器也用同一份代码。

| 位置 | 内容 |
| --- | --- |
| `backend/common/data/` | 职业、武器、角色、技能数据表，数值取自 02、03 |
| `backend/common/engine/` | 确定性战斗引擎：`step(state, action) → { state, events }`；可达范围、交战预测、威胁区等只读查询；规则 AI |
| `frontend/src/battle/` | 战斗页：控制器、事件播放、地图、侧栏、交战演出、对话框 |
| `frontend/src/arena/` | 竞技场：当日对手、禁用、部署、进攻、积分；防守设置页已删除 |
| `frontend/src/pages/`、`frontend/src/watch/` | 军营、名册、转职、整备、生产、酒馆、任务；战报、历史回放与实时观战 |
| `frontend/src/model/` | 由服务端单位推出的名册状态；不再有模板主力／替补／重伤推断 |
| `frontend/test/battle-replay.e2e.mjs` | 在无头 Chromium 中验证服务端竞技场进攻、野外战斗、战报、回放与实时观战空闲态 |

引擎不读时钟，也不用 `Math.random`。随机数用 xoshiro128\*\*，状态保存在战斗状态里；战斗判定和升级成长分成两条随机流。所以「初始状态 + 指令序列」可以完整重现一局，浏览器测试就是靠这一点逐局核对的。

## 已实现的规则

- **移动**：按 03 的地形消耗和四类移动方式计算；敌方单位阻挡通行；友军可以穿过，但不能停在友军所在格。
- **交战**：
  - 攻速、攻击力、伤害、命中、回避、必杀均按 03 的公式。
  - 武器三角、特效 ×3、勇者武器连击、攻速差 4 追击。
  - 飞行单位不享受地形加成。
  - 射程不够时无法反击。
- **判定**：命中取两个随机数的平均值（2RN），必杀取一个随机数。交战预测里的击败概率按这种真实判定逐一枚举计算，界面上显示的命中、必杀仍是规则数值。
- **行动**：攻击、治疗（杖）、伤药、压制、待机，与移动一起原子提交。
  - 压制：只有我方主将、只能在压制地图的王座上执行，执行后立即获胜。
  - 攻击后该武器成为装备武器，之后用它反击。
  - 所有单位行动完后自动结束阶段。
  - 撤退立即判负。
- **经验与成长**：
  - 交战、击败、击败首领、用杖的经验按 03 计算。
  - 升级用纯随机成长，带空级保护（最多重掷 2 次），受职业能力上限约束。
- **地形与胜负**：
  - 站在堡垒、王座上的单位，在所属一方的阶段开始时回复 20% 最大 HP。
  - 胜负条件：击败敌方主将、全歼敌军、压制王座、我方全部退出、回合用尽；压制地图上全歼不算胜利，我方主将被击败即判负。
- **技能**：12 个样例角色的个人技能都已生效，并计入交战预测和治疗预览。
- **规则 AI**：
  - 进攻、伺机、固守、护卫、治疗优先五种行为。
  - 攻击目标按「期望伤害 + 击败概率 × 50 − 期望反击伤害」打分选择，结果是确定的。

## 为实现先定下的暂定规则

以下几项在设计文档里还没有定，引擎先按下面的方式实现。改起来都只涉及一处代码：

| 事项 | 当前做法 | 位置 |
| --- | --- | --- |
| 村庄 | 移动消耗同平地，回避 +10，拜访效果未做 | `maps/map.ts`、03 地形表 |
| 单位 HP 归零 | 战斗层显示为「被击败，退出战斗」；正式 PvE／大竞技场由服务端写回永久死亡与遗产（`services.ts::recordDeath`），普通竞技场与练习仍为模拟副本 | `engine/resolve.ts`、`services.ts` |
| 固守 | 原地不动，只反击。示例关卡的主将用这种行为 | `engine/ai.ts` |
| 回合上限 | 第 20 回合敌方阶段结束仍未获胜即判负（竞技场规则），野外关卡是否设上限待定 | `engine/step.ts` |
| 庇护（诺亚） | 被治疗单位在本回合（含敌方阶段）防 +2 | `engine/skills.ts` |
| 经验与等级 | 总等级 1–99，转职不归零；成长率含个人／职业／成长类型曲线与轮回分配 | `engine/growth.ts`、`game/model.ts` |
| 压制地图的胜负 | 只有压制王座算胜利，全歼守军也要再压制；我方主将被击败即判负 | `engine/step.ts` |
| 规则 AI 的进攻方主将（压制地图） | 王座在移动范围内就压制；否则只打被反杀概率 ≤ 5% 的仗；守军剩 2 人以下才向王座推进，此前原地待命 | `engine/ai.ts` |

## 战斗页

按 08 的「选中单位并预览攻击」设计稿实现。

- **布局**：地图约占 70%，战术栏约 30%，一屏显示，地图和战术栏各自滚动；宽度不足 1100px 时上下排列。
- **操作流程**：选单位 → 预览落点（显示路线）→ 选择行动、武器、目标 → 查看预测 → 确认执行。
  - 在移动范围内直接点敌人，会自动选好站位并打开交战预测。
  - Enter 确认，Esc 逐步返回。
  - 方向键移动光标，空格选择，整个流程都可以只用键盘完成。
- **地图**：
  - 显示可移动（蓝）、攻击范围（红斜纹）、治疗范围（绿斜纹）、敌方威胁区（点状纹理加虚线外沿，T 键开关）、网格（G 键开关）、拟定路线、预览落点和目标标签。标签会避开单位，不遮挡单位。
  - 支持 2× / 3× 整数倍缩放、拖动平移，小地图可以点击跳转。
  - 已行动单位去色并打 ✓，敌方主将带小旗。
  - 压制地图：王座有金色虚线框，选中我方主将或鼠标停在王座上时显示「王座 · 压制目标」；主将的落点在王座上时，行动栏出现「压制」，其他人站上去会提示只有主将能压制。
- **交战演出**：侧视画面，逐击显示伤害和 HP 变化，可跳过。可以选择全部播放、仅主将战或关闭；关闭时伤害数字直接显示在地图上。人物按职业逐个设计（77 个在用职业各一张，骑乘职业带坐骑），阵营换色、肤色发色跟角色头像，手里画这次交战实际用的武器（`backend/common/sprites/`，见像素素材 README）。
- **其他画面**：升级弹窗（逐项显示属性提升）、结束阶段确认（列出未行动的人）、撤退确认、胜负结算（胜负、回合数与战败原因，不设星级评价）、战况记录。
- **资源**：像素素材直接取自 `design/pixel-art/png`。像素字体 Silkscreen 打包在项目里，中文使用系统字体，页面不请求任何外部资源。

## 竞技场进攻流程

按 [05](05-arena.md) 与 [30](30-ui-update-design.md) 实现：竞技场首页（当前记录的 3 个对手）→ 查看对手并禁用 B 人（名单按等级排序，不暴露站位和 AI）→ 揭晓实际出战的 D 人、站位和对方对我方的预设禁用 → 从自己的实例名册中选 D 人、指定主将、在出生区摆位 → 进攻方先手开战（不给经验，可投降）→ 计分并保存回放。

- 规则在 `backend/common/arena/`：`maps.ts`（塔林原野 6+2、灰岩隘口 5+1、暮影林地 4+2、王城 8+3）、`rules.ts`（实例禁用、编成校验、同形象限制、生成战斗、计分）、`demo.ts`（官方兜底队伍）。
- 普通竞技场每场入场推进 1 日；三场可以跨日继续。只有三场都结束，或日历走到下一个竞技场日时，剩余没打的场次才按落败结算；后台扫描不会在两次进攻之间吞掉剩余场次。
- 同一形象只能上一人：服务端按 `portrait` 校验，出战名额也按可用形象数封顶；同模板的不同实例仍可在其他场次分别出战。
- 进攻状态由服务端保存，刷新或暂离后继续同一场；前端不再保存本地演示进度，也没有“重置今日进攻”的演示按钮。
- 王城 20×14：护城河上一座桥、两处浅滩，三道城门，王座在大厅最里面 `(18,7)`。禁用页地图放不下 2 倍时改用 1 倍显示，不做非整数缩放。
- 普通竞技场使用模拟战副本，不产生永久死亡，也不回写真实耐久／次数。

## 已移除的防守设置

`#/arena/defense` 不再提供防守编成；旧地址会回落到普通竞技场页。`GET_DEFENSE`／`SET_DEFENSE` 只为读取或兼容旧存档保留，不再是进攻前置。旧版防守地图、名单优先级、AI 行为、主将顺序和预设 BAN 的页面说明只属于历史。

## 页面现状

所有页面读写服务端数据（GET_STATE / GET_TODAY / GET_ARENA / GET_ROSTER / GET_QUESTS 等）；顶栏显示个人日期与下个事件（竞技场日）。

| 页面 | 地址 | 真实内容 | 仍是演示或待做 |
| --- | --- | --- | --- |
| 军营 | `#/camp`（首页） | 个人日期与季进度、待办（进行中的战斗、今日或下一个竞技场日、上次结果）、行动（耗日、金币与推进到的日期来自 GET_TODAY）、重要日期、Agent 上报的计划 | 真实多人压力 |
| 出击 | `#/field` | 出征准备：地区敌方等级与讨伐状态、队伍（上限取 GET_TODAY）、胜利条件、回合上限、推进日期与阵亡风险；确认后才 SORTIE，未完的野外战斗会续上 | 逐图手感验收 |
| 名册 | `#/roster/<id>`、`/growth`、`/mastery`、`/classes`、`/retire` | 属性与合计成长、装备、升级记录、精通与五格技能、职业资格、退役与轮回、竞技场快照对比 | 旧存档迁移 |
| 转职 | `#/roster/<id>/promote` | 相邻职业转职、服务端成长预览、资格校验 | 特殊机制职业仍按 00 边界 |
| 竞技场 | `#/arena` | 当前记录的 3 场进攻（禁用 → 部署 → 战斗）、积分、金币、现实月榜；没有玩家防守 | 月奖数值校准 |
| 整备 | `#/prep` | 仓库、商店、携带物、维修、书次数、能力药与公共经验；不推进日期 | — |
| 生产 / 酒馆 | `#/workshop`、`#/tavern` | 工位／订单／成熟日期；季度候选、付费雇佣、小游戏和免费补员 | 经济参数校准 |
| 任务 / 挑战塔 | `#/quests`、`#/quests/tower` | 地区任务、声望、经典地图；塔层、首通／重复奖励 | 内容量继续扩充 |
| 主线 / 传承 | `#/story`、`#/legacy` | 八章事件与公共经验；遗产、纪念名册、继承预览、轮回 | 正式内容制作 |
| 战报 / 观战 / 回放 | `#/replay`、`#/spectate`、`#/replay/<id>` | 活动／结果／日期筛选、伤亡与消耗、关联战斗；实时观战只读轮询；历史回放逐步查看 | 推送式实时观战与公开时点 |
| 规则 / 设置 | `#/rules`、`#/settings` | 规则数字读共享数据；Agent 令牌、控制租约、显示默认值 | 更多权限范围 |

- 回放把引擎一次结算的敌方阶段按单位拆成步骤，每一步的局面由事件重建，与引擎终局逐项一致（单位位置、HP、存活、等级、属性）。
- 实时观战没有进行中的战斗时明确显示空闲态并链接历史战报，不再自动播放最近回放冒充实时。
