# 随机战场地图生成工具

状态：可运行的独立原型，不依赖游戏服务、数据库或第三方 npm 包。正式地图尺寸尚未确定，20×20 只是工具默认值。

## 快速使用

需要 Node.js 22.18+（本次在 Node.js 24.20.0 验证）。原生运行 TypeScript，无需安装依赖或先编译。

在项目根目录运行：

```bash
# 终端预览，省略种子时生成随机种子并显示
node tools/mapgen/cli.ts

# 20×20、固定种子，生成 JSON
node tools/mapgen/cli.ts --width 20 --seed forest-01 --format json --out map-20.json

# 同参数生成 SVG，用浏览器打开即可查看
node tools/mapgen/cli.ts --width 20 --seed forest-01 --format svg --out map-20.svg

# 比较 25×25；高度默认等于宽度
node tools/mapgen/cli.ts --width 25 --seed forest-01 --format svg --out map-25.svg

# 指定场景主题，例如王宫内
node tools/mapgen/cli.ts --theme palace --width 25 --seed palace-01 --format svg --out palace.svg

# 非正方形也可以，每方 8 个出生点
node tools/mapgen/cli.ts --theme mountain --width 28 --height 18 --units 8 --seed valley-02

# 校验已有 JSON（包含结构检查）；无效时退出码为 1
node tools/mapgen/cli.ts --check map-20.json

# 测试
node --test tools/mapgen/mapgen.test.ts
```

`--out` 只创建新文件，拒绝覆盖已有文件；父目录需要存在。不提供输出路径时，结果写入标准输出。`--check` 不与生成参数混用。

当前允许宽、高各 10–64，每方 1–8 个出生点，均为原型边界，不是正式地图规格。种子为 1–200 字符字符串。

已生成的示例：

- [20×20 SVG 预览](../tools/mapgen/examples/map-20.svg) / [JSON](../tools/mapgen/examples/map-20.json)
- [25×25 SVG 预览](../tools/mapgen/examples/map-25.svg) / [JSON](../tools/mapgen/examples/map-25.json)

SVG 是地形与部署位置的功能预览，配色取自像素素材的色板，但不是像素美术。

## 场景主题

通过 `--theme` 选择，默认 `grassland`。主题会改变地形生成结构和地面类型，不是单纯换皮。

| 参数 | 场景 | 布局特点 | 示例 |
| --- | --- | --- | --- |
| `grassland` | 草地 | 开阔平原、成片树林、少量山地、可能有河道 | [预览](../tools/mapgen/examples/map-20.svg) |
| `city` | 城市 | 密集建筑街区、石地板路网、中央空地 | [预览](../tools/mapgen/examples/city.svg) |
| `palace` | 王宫内 | 石地板、外墙、室内分隔、门口与走廊，不生成室外山林水域 | [预览](../tools/mapgen/examples/palace.svg) |
| `town` | 城镇街道 | 较疏散的房屋、十字道路、树木与空地 | [预览](../tools/mapgen/examples/town.svg) |
| `mountain` | 山地 | 大片山地、谷道、局部树林与可能的河道 | [预览](../tools/mapgen/examples/mountain.svg) |
| `forest` | 树林 | 高覆盖率森林、林间空地与可能的河道 | [预览](../tools/mapgen/examples/forest.svg) |
| `riverlands` | 大河浅洲 | 宽河道、浅洲与过河桥；加入瓦恩要塞的普通野外遭遇池 | `--theme riverlands` |
| `lakeland` | 湖心群岛 | 大片湖面、浅滩岛屿与桥网；加入莱斯米尔湖镇的普通野外遭遇池 | `--theme lakeland` |

两种新野图与各地区原有布局按战斗种子择一生成，不替换任务／副本地图。20×20代表种子在通路修复后仍保留至少25%的水域；冬季出发时由战斗创建层将水域、浅滩转成冰面，草地转成雪地，详见[03](03-combat.md)。生成器本身不读取日历，老主题的同种子结果保持不变。

地形种类、字符和移动规则以 [03 战斗规则](03-combat.md) 的地形表为准，和[像素素材](../design/pixel-art/README.md)共用一套字符。城市和王宫内的地面是石地板，城镇的十字主街是道路，其他主题的空地是平地，三者移动规则相同。房屋的不可进入主体用墙壁表达，没有进入建筑、开门、屋顶飞越等新规则。宫殿门口是常开通路，不引入钥匙或锁门。生成器目前不放置村庄。

所有主题都经过同一套通路修复与校验；连通性优先，必要时会局部开通墙体或山脊。

## 当前生成内容

- 按主题生成的地形簇、建筑街区或室内房间，以及少量堡垒。
- 左侧己方出生点、右侧敌方出生点，各点互不重叠。
- 敌方区域附近的王座，作为可达性测试与压制目标。
- 一条较宽的基础行军通路，并按需要修复其他断开的区域。
- 可复现的种子、生成器版本、主题、地形矩阵、出生点与目标坐标。

不生成角色数值、职业名单、敌方 AI 行为、掉落或完整战斗配置；出生点不等同于已经部署好的单位。

## 保证哪些事情

地形移动消耗来自 [03 战斗规则](03-combat.md)，存储在 `backend/common/maps/map.ts`，生成器、校验器与预览共用该定义。

分别检查步行、重甲、骑乘、飞行四类移动方式：

1. **每类可进入的所有格子属于同一个四方向连通区域。** 不仅连出生点与目标，也检查孤立山地、水域等特殊移动区域；飞行不能穿墙。
2. **双方每个出生点与王座对四类移动均可达。** 因此替换当前职业中的任意移动类型，不会出生在不适合自己的地形上。
3. **每个出生点至少有一个未被出生单位占据的可进入邻格。** 初始部署不会让角色完全无法迈出第一步。
4. **进入路径上每格的消耗不超过该移动类型当前最低移动力。** 步行 5、重甲 4、骑乘 7、飞行 7，取自现有职业表；不把一格无法支付的消耗误判为可以跨回合通过。
5. **非法输入直接报错。** 未知地形、越界坐标、错误尺寸、出生点重叠、目标不匹配等不会静默接受。

上述保证假设地形静态、使用当前职业移动力，路径可以跨多个阶段完成。未来新增移动类型、降低移动力、引入门锁或动态地形时，必须一起更新校验规则。

生成后的敌人必须部署在经过校验的出生点；如果以后把飞行敌人放在任意水面或山顶，需要额外检查地面单位是否有可用攻击位置，不能继承当前保证。

## 不保证哪些事情

地图连通不等于战斗必胜：

- 单位占位、敌军堵路、不朽盾石化占位等动态情况不在静态连通检查中。
- 不检查攻击范围、敌我战力、装备、AI 行为或随机战斗结果。
- 不保证在某个回合数内能获胜，也不预设正式回合上限。
- 不保证竞技攻防平衡，也不强制每处都有双通路或没有狭窄隘口。

当前设计接受由战斗的回合截止规则处理部分动态特殊场景，不为所有动态僵局增加地图修复逻辑。回合截止由未来战斗引擎负责，本工具不实现计时器，也不擅自决定回合上限。

## 算法与复现

1. 按种子和主题生成地形、街区或房间。
2. 放置出生点与目标，并清理周围部署空间。
3. 通过随机中间点开辟基础路线。
4. 依次查找重甲、步行、骑乘、飞行的孤立区域，将孤立区域接到公共地面通路。
5. 完成后重新运行独立校验；校验不通过则报错，不导出不合格地图。

修复只改动路线经过的格子：变成该主题的地面（平地或石地板），已有的道路和桥保持不变；经过水域或浅滩的格子铺成桥。路线顺着河道走时，桥会沿河排成一列。清理部署空间时同样保留道路和桥。

为了保证终止，修复每次连接一个此前不可达的格子，并且不会删除已有通路。地图尺寸有上限，不依赖无限随机重试。

相同生成器版本、主题、种子、尺寸、人数产生相同地图。当前为 `generatorVersion: 3`（地形表与像素素材统一后的格式），不接受 v1、v2 的旧 JSON；重新按所需参数生成即可。修改生成算法时需升级 `generatorVersion`；正式对局应保存完整地图快照，不仅保存种子，以免未来版本改变回放。地图随机数仅用于此原型，不代表已经选定战斗引擎的随机算法。

## 数据与代码位置

| 文件 | 职责 |
| --- | --- |
| `backend/common/maps/map.ts` | 地形与移动规则、字符与预览配色、数据结构、连通搜索、外部地图校验 |
| `backend/common/maps/generate.ts` | 带种子的纯函数地图生成与通路修复 |
| `backend/common/maps/themes.ts` | 八种主题的布局规则与地面类型 |
| `tools/mapgen/cli.ts` | 参数解析、文件读写与退出码 |
| `tools/mapgen/render.ts` | ASCII 与 SVG 预览 |
| `tools/mapgen/mapgen.test.ts` | 批量连通性、异常地图、复现及命令行测试 |

坐标使用 `[x, y]`，左上角为 `[0, 0]`；地形读取为 `tiles[y][x]`。`objective.kind` 当前仅为 `seize`，这不是完整战斗协议。生成器内部不读取时钟、不使用 `Math.random`，只由 CLI 在未指定种子时生成随机种子。

## 20×20 还是 25×25

暂不锁定。25×25 有 625 格，比 20×20 的 400 格多约 56%，在人数不变时更容易增加赶路时间，也可能为迂回提供空间。实际节奏仍取决于部署距离、地形、移动力与目标。

建议用同样人数各试几张，记录：首次接敌回合、空走回合、战斗总回合、回合截止比例和 Agent 指令成本，再确定正式尺寸。当前代码同时支持两者及长方形，不需要先决定尺寸才能使用。

测试覆盖 8 个主题 × 100 个种子 × 4 组尺寸的 3,200 张地图，另外检查各主题最大尺寸和狭长地图；使用额外独立遍历核验连通性，并测试主题结构差异、水域阻断、孤岛、被封闭目标、非法 JSON、SVG 转义、文件覆盖保护、过河铺桥，以及地形字符与像素画法是否一致。
