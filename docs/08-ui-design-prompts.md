# UI 设计提示词

## 设计方向与使用方式

**羊皮纸军团手册 + 经典像素战场 + 现代网页交互。**

羊皮纸负责氛围，像素人物与地图负责游戏感，清晰的排版和操作反馈负责易用性。不要把整个画面都做成泛黄古卷，也不要把所有文字都变成像素字体。

本套提示词依据项目游戏总览、角色成长、战斗、养成日历、大竞技场和 Agent 接口设计整理。它是 UI 设计建议，不替代游戏规则；大纲中的待定数值仅用作示例。

使用时先发送「总提示词」，再附加一个「页面提示词」和末尾的「通用约束词」，逐页生成。建议先设计战斗页、角色名册、军营首页，统一视觉后再扩展竞技场与观战回放。

## 1. 总提示词：统一视觉与交互

```text
请为一款原创中世纪奇幻回合制战棋网页游戏设计高保真 UI，暂用名 AgentTactics。

【产品定位】
这是一款具有经典火纹式战棋体验的网页游戏：
核心玩法是角色招募、职业成长、装备整备、网格回合制战斗，以及带禁用角色机制的异步竞技场。
玩家既可以亲自操作，也可以观看自己的 AI Agent 游玩。

界面需要有鲜明的游戏感，并适合长时间阅读属性、比较角色、制定战术。
可以有较多文字，但必须结构清晰、层级明确，避免说明书式的大段堆砌。

【核心美术方向】
现代化的像素战棋 UI，结合克制的羊皮纸军团手册风格。
关键词：
精致像素、军团名册、战术地图、浅色羊皮纸、深蓝战旗、旧黄铜、清晰排版、紧凑而舒适。

参考经典掌机时代战棋游戏的地图、单位精灵和战斗信息表达。
角色、纹章、世界观与图形资产全部原创，不使用火焰纹章已有角色、标志或美术资产。

整体应像一本正在使用的军团作战手册：
实用、整洁、有故事感，不过分破旧，也不奢华。

【视觉分工】
1. 战斗地图、地图单位、角色头像、武器图标采用统一尺度的精致像素美术。
2. 面板、导航、表格、按钮使用清晰的现代网页布局。
3. 羊皮纸质感主要用于页面背景、角色档案与信息面板。
4. 战斗地图保留自然的绿色森林、灰色石墙、蓝色河流，不套泛黄滤镜。
5. 旗帜、纹章和细线边框只作为少量识别元素，不占据主要操作空间。

【配色】
页面底色：暖灰米色 #E8E1D3
面板底色：浅羊皮纸色 #F5EEDF
主要文字：深墨褐色 #302D28
辅助文字：灰褐色 #6A6256
主要操作与己方标识：沉稳深蓝 #34556B
敌方与危险标识：暗朱红 #A84940
确认与恢复标识：苔绿色 #536D49
重点与选中描边：旧黄铜色 #A88445

保持正文与底色的充分对比。
不使用大面积纯金、霓虹、强发光或高饱和渐变。

【文字与信息密度】
界面使用简体中文。
正文、按钮和属性使用清晰易读的现代中文字体。
少量页面标题可以使用有书卷气的宋体。
像素字体只用于少量装饰性英文或数字，不用于中文长段落。

主要正文建议 14–16px，关键数值更突出。
属性和装备使用对齐的列表或表格，便于横向比较。
优先呈现当前决策需要的信息，公式、历史记录和详细说明按需展开。
角色技能采用“技能名 + 一句效果”，避免大段背景故事挤占操作区。

【布局与组件】
以 1440×900 桌面浏览器为主要设计画布。
使用稳定的顶部状态栏、紧凑导航和明确的主要内容区。
管理页面允许列表与详情并排，战斗页面让地图占据主导位置。
使用细边框、小圆角、轻微阴影，纸纹应低对比、近乎不可察觉。

按钮需要有默认、悬停、按下、选中、禁用与键盘焦点状态。
主要按钮使用深蓝实底，次要操作使用浅底描边。
图标配文字，不能仅靠模糊的图标表达核心功能。
危险操作与常用操作拉开距离。

颜色不能成为唯一的识别方式：
阵营、选中状态、禁用和已行动状态同时使用描边、符号或文字辅助表达。

【体验目标】
玩家进入页面后，应迅速知道：
我现在处于什么阶段；
有哪些资源与限制；
当前最值得处理的事项；
点击后会发生什么。

吸引力主要来自有性格的像素角色、鲜明的战场、精致的排版与明确的操作反馈。
请让它看起来是一款真正可以连续游玩的战棋游戏。
```

## 2. 战斗页：优先确定整体气质

经典火纹感来自方格走位、兵种辨识、双方预测和短交战演出；现代化主要体现在信息更好读、操作更顺手。

```text
沿用总提示词的视觉规范，设计一张正在操作中的战棋战斗页面。

【场景】
一场原创的森林隘口战斗。
正俯视二维方格地图，包含森林、石桥、河流、道路和小型堡垒。
采用清晰的像素地形与像素单位，不使用等距视角、六边形网格或写实 3D。

地图约占主要内容区的 70%，右侧约 30% 为战术信息栏。
保持方格等宽等高，单位轮廓、地形与覆盖提示均能辨认。
较大地图支持平移和缩放，不能为了塞进一屏而把单位缩得无法辨认。

【顶部】
展示：
关卡名称、当前回合、己方或敌方阶段、胜利条件。
本示例使用“第 4 / 20 回合 · 己方阶段”“胜利条件：击败敌方主将”。

【地图交互】
选中一个己方剑士：
用清晰的边框标出当前格；
半透明蓝色表示可移动区域；
红色边界或浅色网纹表示攻击范围；
可开关的敌方威胁区使用另一种纹理，避免与攻击范围混淆；
拟定移动路线使用简洁箭头。

友军与敌军通过底座、轮廓和阵营颜色区分。
已行动单位降低饱和度，并带已行动标记。
主将带小型旗帜标识。
覆盖区域不能遮住地形与单位。

【右侧信息栏】
默认显示选中单位：
原创像素头像、姓名、职业、等级、HP、当前武器、关键战斗属性与技能摘要。

选择攻击目标后，信息栏切换为经典双方交战预测：
双方姓名与武器；
当前 HP；
伤害、命中、必杀；
追击次数，例如“伤害 12 × 2”；
武器克制与特效提示；
无法反击时明确写“无法反击”。

命中率与必杀率必须作为概率展示，不能把预测结果画成已确定发生的伤害。

【操作】
操作流程：
选单位 → 预览落点 → 选择行动、武器和目标 → 查看预测 → 确认执行。

确认前只是路线和行动预览，可以取消；
确认后一次提交移动与行动，不能展示提交后撤销的按钮。

行动菜单提供攻击、治疗、道具、交换、压制、待机等当前可用选项。
按场景显示适用项，不把所有按钮同时堆出。
“结束阶段”位于固定位置，与“确认攻击”保持明显距离。
仍有未行动单位时，结束阶段应提示剩余人数。

【下方】
保留紧凑的事件记录，可折叠。
用简短文字表达命中、闪避、伤害、撤退与升级，不展示原始技术日志。

【交战表现】
额外展示一个可跳过的短交战演出状态：
原创侧视像素人物、双方 HP 条、伤害数字与简洁动作。
演出结束回到同一张战术地图。
该演出作为独立状态稿，不在主战斗画面中永久占据空间。

请优先输出“选中单位并预览攻击”的完整页面，
确保地图、交战预测和确认按钮同时清晰可见。
```

## 3. 军营首页：文字较多的页游体验

```text
沿用总提示词，设计军营首页。
整体像一份清晰的军团当月作战简报，有轻微羊皮纸质感和少量战旗元素。

顶部状态栏显示：
赛季、当前游戏月、剩余行动日、金币、奖励经验。
行动日是赛季内可累积的行动预算，不画成随时间恢复的体力槽。

主导航包含：
军营、名册、出击、整备、竞技场、战报。
Agent 状态作为紧凑入口，不占据主要导航空间。

主体采用清晰的两栏结构：
左侧主要区域展示本月事务与行动入口；
右侧展示军团概况、重要时间和 Agent 简报。

本月事务按优先级呈现：
进行中的战斗、月末主线、竞技场报名、下一次快照锁定时间。
每项包含一句说明、当前状态和一个明确操作入口。

行动区提供：
出击、扫荡、训练、休整、游历。
每个入口用小型像素图标、名称、一句作用和行动日消耗表达。
不要使用五张巨大的营销卡片。

军团概况展示：
名册人数、重伤人数、几名主力的像素头像与等级。

Agent 简报展示：
在线或离线状态、本月培养计划、最近一次行动。
计划采用简短自然语言，例如“优先提升弓兵武器等级，为月末攻城做准备”。
不要把它做成占据半屏的聊天窗口。

页面以可操作事项为中心，不使用大幅无功能的城堡背景图。
日期、资源和进度使用示例数据，不将设计草案数值固化为规则。
```

## 4. 角色名册与转职：便于比较的军团档案

```text
沿用总提示词，设计角色名册与角色详情页面。

采用左侧名册列表、右侧角色档案的双栏布局。
角色列表信息紧凑，支持按职业、等级、成长类型和重伤状态筛选或排序。

列表每行显示：
像素小头像、姓名、职业、等级、成长类型与状态。
选中行使用深蓝标识和轻微底色变化。

详情使用原创剑士“艾琳”作为示例：
顶部显示中等尺寸像素头像、姓名、职业、等级、经验与个人技能。
头像应有角色辨识度，但不挤占属性与装备区域。

属性使用整齐的数值表：
HP、力、魔、技、速、运、防、魔防、体格、移动。
成长信息分清个人成长率、职业成长率与合计成长率。
明确表达成长率是每次升级的概率，不表示确定获得的属性。
不要用难以精确比较的大型雷达图代替数值表。

装备区域显示最多 5 件携带物品：
区分当前装备、其他武器与消耗道具。
武器显示等级要求、威力、命中、重量、射程等必要信息。
武器没有耐久，不设计修理入口或武器耐久条。

次级标签包含：
属性与装备、成长记录、转职。
成长记录展示历次升级的实际属性增加，以及按月快照对比。

额外设计转职面板：
剑圣与刺客两个分支并排比较，
重点显示立即获得的属性变化、武器权限、移动力、职业技能和未来成长率变化。
清楚显示条件、转职印消耗和确认按钮。
不将转职做成复杂的发光技能树。
```

## 5. 竞技场：清晰表达禁用与快照规则

```text
沿用总提示词，设计异步竞技场的赛前准备界面。
保留克制的竞技氛围，使用深蓝与暗红的对阵标识，不使用大型奖杯与满屏金色特效。

展示清楚的流程：
查看对手 → 禁用角色 → 揭晓阵容 → 我方部署 → 开始战斗。

主要设计“查看对手并选择禁用角色”的状态：
左侧为防守名单，显示角色头像、职业、等级、完整属性与装备查看入口；
右侧为地图预览、地图规则和已选禁用角色；
底部显示已禁用人数与确认按钮。

出战人数、禁用人数、回合上限和胜利条件均由当前地图决定。
可以用“塔林原野：出战 6 人、禁用 2 人、20 回合”作为本稿示例，
但不能把该人数设计为所有地图固定不变的布局。

禁用确认前：
可以查看地图地形与防守名单；
不能展示敌方实际站位或 AI 行为。

禁用确认后：
揭晓实际防守阵容与站位，展示我方被禁用的角色；
进入我方选择出战人员、指定主将和部署位置的界面。
对手 AI 行为仍不可见。

清楚标注“使用本月锁定快照”。
让玩家能区分当前养成中的角色与本次竞技场快照，避免误以为临时换装备可以影响本次对局。

另外给出防守设置页面：
选择地图、配置防守名单、调整优先级、设置站位、
设置每个单位的行为、主将与备选主将、预设禁用角色。

只在配置自己的防守时展示 AI 行为选项。
优先级调整同时提供按钮操作，不能只支持拖拽。

比赛结果展示胜负、积分和回放状态。
尚未到公开时间的他人回放，显示公开时间与锁定状态。
```

## 6. Agent 观战与回放

```text
基于同一套战斗 UI，设计 Agent 观战与历史回放状态。

观战时突出地图、当前行动单位、阶段变化与战斗结果。
右侧展示 Agent 已上报的本阶段意图，例如“重甲守桥，飞行单位绕后”。
明确区分 Agent 的计划描述与已经实际发生的战斗事件。
未上报时显示暂无说明，不虚构 Agent 的内心推理。

历史回放提供播放、暂停、倍速、上一步、下一步与回合定位。
事件列表与地图联动，便于查看关键击杀、撤退与升级。

实时观战与历史回放具有明显标签。
实时观战不展示可以改变战局的按钮；
回放不显示攻击、待机、结束阶段等实战提交按钮。
界面保持游戏观战体验，不展示 JSON、协议号或开发调试日志。
```

## 7. 通用约束词：每次生成时附加

```text
避免：
厚重雕花边框、大面积卷轴卷边、烧焦纸张、强烈污渍、
满屏蜡封、齿轮与装饰纹章、金色浮雕、巨大装饰性标题、
霓虹发光、玻璃拟态、写实 3D、等距或六边形战场、
手机抽卡大厅、满屏红点、巨幅角色立绘、无功能的背景插画、
所有文字像素化、细小灰字、密集嵌套卡片、关键操作仅用图标、
把整款游戏做成缺少角色与战场表现的通用数据后台。

请输出真正的游戏界面，而不是游戏官网、宣传海报或设备展示模型。
每次只展示一个主要页面状态；其他交互状态单独出稿。
界面内使用有意义的中文示例内容，不用大段占位文字。
```

## 出图检查重点

- 战斗地图是否保留清晰的像素地形、方格走位和兵种辨识。
- 交战预测、确认操作与地图是否能同时看清。
- 中文正文与属性数字是否易读，纸纹是否干扰阅读。
- 名册与转职是否方便比较，重要信息是否被装饰挤占。
- 竞技场禁用前是否隐藏站位，是否始终隐藏对手 AI 行为。
- 管理页和战斗页是否共享同一套配色、字体与组件风格。
