# 架构与表现技术决策（首版）

更新：2026-10-18。本文把 [07](07-architecture.md) 的待定项落成首版边界，避免继续用“以后再说”作为实现阻塞。

## SQLite

- 首版继续使用 Node 内置 `node:sqlite`，单库、WAL、外键开启；`DB_PATH` 可配置。
- SQLite 足够承载首版单机/小规模多人、快照、回放、月度榜和后台任务。
- 触发 PostgreSQL 迁移的条件：需要多进程高并发写入、跨机器共享、在线扩容、行级锁/长事务，或单库备份窗口无法满足运营 SLA。
- 迁移工具选择：优先 `drizzle-kit` 或纯 SQL 迁移目录；迁移前必须能导出规范化 JSON/SQL 快照。首版不引入 ORM 运行时。

## 回放与规则版本

- 战斗继续保存 `initial` 状态、seed、动作序列和最终 `state`；`BattleState.engineVersion` 保留。
- 旧回放策略：优先使用保存的最终 `state` 展示；需要逐步重算时校验引擎版本，不匹配则拒绝重算并提示查看存档结果，不用新算法静默覆盖旧结果。
- 后续新增 `rulesetVersion`/`catalogVersion` 时，活动、快照、回放和年度报名一起冻结版本。

## 表现层

- 首版继续 DOM/CSS 战术棋盘，不引入 Canvas/PixiJS；现有拖动、缩放、小地图、物件层和键盘操作已够用。
- 当同屏单位/特效达到 DOM 性能瓶颈，或需要逐帧粒子/大量动画时再评估 PixiJS；切换不得改变引擎状态和回放语义。
- 首版不引入 WebGL 渲染器；像素美术继续走现有 sprite/图层资源。

## 数据与隐私

- 玩家、战斗、回放均按 `playerId` 隔离；公开回放只允许读取已结束且公开的记录。
- Agent token 与网页会话分离，后续补 scopes、过期和撤销；首版不把 Agent token 当作网页登录凭据。
- 备份/恢复流程见 [28](28-release-readiness.md)。

## 不在本轮引入

- 多版本引擎并行、事件溯源数据库、消息队列、外部对象存储。
- 这些只在首版真实压力或多机部署需要时再决策；PRNG 已有实现，不从零重做。
