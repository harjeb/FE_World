# 界面更新设计（2026-10-18）

更新：2026-10-18。本文记录本轮服务端接入与界面调整的页面级设计，不替代 [00 游戏设计](00-game-design.md)、[08 UI 提示词](08-ui-design-prompts.md) 或 [28 交付边界](28-release-readiness.md)。凡本文与旧页面说明冲突，以本文和当前运行时为准。

## 1. 目标

本轮界面更新解决三类问题：

1. **去掉演示数据依赖。** 名册、日期、金币、战斗、任务、生产、竞技场和战报全部读服务端状态；页面不再用模板主力／替补、固定武器阈值或本地模拟推进真实对局。
2. **按最终规则收起防守玩法。** 普通竞技场只主动进攻，不再提供防守编成入口；旧地址回落到竞技场页。
3. **补齐长期管理页。** 把酒馆、派遣、战报、实时观战、挑战塔和传承确认做成可日常使用的页面，而不是一次性演示稿。

## 2. 导航与页面框架

- 主框架由顶栏、左侧导航和内容区组成；顶栏显示个人日期、下个事件、金币、公共经验、竞技场积分、Agent 在线状态和控制权。
- 导航按日常动线排序：**军营、名册、出击、任务、整备、生产、酒馆、竞技场、主线、传承、战报**；规则手册放在底部，设置放在顶栏。
- 所有会推进日期的操作在按钮或确认框上写明将推进到哪一天；不推进日期的整理操作单独标注。
- 所有页面共享加载、空状态、权限不足和旧回放不可重算的提示样式；不在页面里展示 JSON、协议号或开发调试日志。

## 3. 页面范围

### 3.1 军营与名册

- 军营待办按“现在能做什么”排序：主线、任务领奖、生产成熟、遗产、寿命预警、竞技场、招募候选。
- 名册只展示真实单位实例：姓名、形象、职业、等级、HP、状态、年龄、寿命预警、身份来源（主角／固定人物／招募）。
- 单位详情拆为属性、成长记录、精通与技能、职业资格、退役与轮回五个分页；属性页的合计成长由服务端计算，页面不自行拼加。
- 同一形象可以有多个单位实例；显示以实例 id 为准，竞技场出战、传承和纪念也不能只按 character 锚点判断。

### 3.2 整备

- 仓库、商店、携带物、维修、法术书次数、能力药和公共经验分配集中在一页。
- 买卖、装备、分配公共经验和修理不推进日期；旅馆与食物会消耗日期并明确显示目标书。
- 从仓库放入、交给队员、使用能力药和出售材料都有服务端回执；刷新后以服务器库存为准。

### 3.3 出击、副本与派遣

- 出击先进入出征准备：地区、队伍、敌军等级、回合上限、永久死亡风险、耗日和目的地日期都在确认前可见。
- 三图大副本按图支付日期，跨图保留 HP、道具和武器；撤离保留已发生伤亡，不返还已付日期。
- 背景派遣单独成页：自选人员、地点和天数，按个人日历并行推进；派遣中的角色不能参加其他战斗。

### 3.4 普通竞技场（仅进攻）

- **只保留进攻。** 报名后生成当日对手；进攻流程为查看对手 → 禁用 → 揭晓 → 部署 → 战斗 → 结算。
- 每场进攻入场推进 1 日。三场进攻可以跨日继续；只有三场都结束，或日历到达下一个竞技场日时，剩余没打的进攻才按落败结算。后台扫描不会在两次进攻之间把剩余场次判负。
- 竞技场按单位实例锁定名单和战斗；**同一形象的两名角色不能同时上场**。服务端校验 `portrait`，不只是 character 锚点。
- 普通竞技场是模拟战：不产生真实伤亡，不回写真实消耗，不发等级经验；奖励为金币、积分和现实月榜。
- 旧的 `#/arena/defense` 入口不再提供防守编成，打开时回落到竞技场页。

### 3.5 年度大竞技场

- 报名时锁定名单、快照和物资；海选三场至少两胜，正赛六轮单败。
- 每场推进 2 日；页面直接显示下一场地图、出战人数、回合上限和真实死亡风险。
- 退赛、淘汰和未参赛都保留对应说明；主线章节不被名次阻断。

### 3.6 任务与挑战塔

- 地区任务按地区分组，显示声望档位、前置、目标、敌军等级、人数上限、日期和奖励；领奖与接取分开。
- 挑战塔单独分页，显示层数、地图、固定敌军等级、首通／重复奖励和第八章后开放条件。
- 经典地图只作为来源与关卡内容，玩家可见的作品名／章节名使用本作原创命名；原始来源仍保存在内容数据的 `source` 字段。

### 3.7 酒馆与生产

- 酒馆显示季度付费候选、价格、等级和是否已雇佣；候选不因刷新重掷。小游戏与免费紧急补员在同一页，但分别标注额度和风险。
- 生产页显示工位、订单、成熟日期和可领取状态；开工不耗日，播种耗日，成熟靠推进日历。

### 3.8 主线、传承与纪念

- 主线按年开放章节，完成事件与领取团队公共经验分开；锁定章节不显示标题。
- 传承页显示来源、冻结的个人成长、两种传承方式、继承者条件、所需石头和逐级保底；预览与执行使用同一套规则函数。
- 轮回页显示回到 1 级后的属性、清除项（含已学技能与已学战技）、保留项、年龄和花费；真实服务器预览与执行一致。
- 纪念名册保留最终状态、死亡经过或退役、参战记录、遗产和继承关系。

### 3.9 战报、回放与实时观战

- 战报页按活动、结果、日期范围筛选，可只看自己的记录或包含其他军团已公开的竞技场对局；列表显示胜负、日期、回合、阵亡和活动标签。
- 详情显示伤亡、道具／耐久／法术次数消耗、升级与战利品、出手统计、Agent 说明，并链接同一次远征或同一届赛事的其他战斗。
- 回放只读，不显示可以改变战局的按钮；规则版本不兼容时只展示保存的终局，不用新规则重算。
- 实时观战读取当前进行中的战斗，按事件游标增量拉取并只读播放；断线后退避重试并从断点续看。没有进行中的战斗时明确区分“实时”与“历史回放”，不自动播放最近一场冒充实时。

### 3.10 规则手册与设置

- 规则手册的数字从共享游戏数据读取（日历、竞技场地图、生产配方、奖励等），不在页面硬编码。
- 设置页负责账号、Agent 接入令牌、控制权租约和战斗显示默认值；Agent token 与网页会话不共享权限。

## 4. 视觉与交互约束

- 延续浅色羊皮纸、深蓝战旗、旧黄铜和像素素材；装饰不能挤占属性、日期、风险和费用等信息。
- 关键操作有明确的禁用条件和原因；失败时给出可执行的下一步，不只显示错误码。
- 长列表使用表格或紧凑行，移动端允许横向滚动；不在战报或名册里用省略号隐藏决定胜负的数值。
- 任何“确认”步骤都说明不可逆影响：永久死亡、退役、轮回、退赛、消耗石头或核心。

## 5. 验证

本轮界面与规则改动的验收覆盖：

```powershell
npm.cmd --prefix backend test
npm.cmd --prefix frontend run typecheck
npm.cmd --prefix frontend run build
node frontend/test/backend-integration.e2e.mjs
node frontend/test/battle-replay.e2e.mjs
node frontend/test/systems.e2e.mjs
```

三个浏览器脚本分别覆盖：真实服务端数据与新档、战斗／竞技场／回放／观战、永久军团各管理页。新增的竞技场跨日结算、同形象上场限制、随机招募个人成长持久化、舞蹈距离和轮回清空战技都有后端测试；页面仍以服务端返回为准，不以浏览器缓存断言结果。

## 6. 仍然保留的边界

- 实时观战是轮询式只读订阅，不是 WebSocket 推送；多连接控制权与真实多人压力仍按 [28](28-release-readiness.md) 的边界验收。
- 战报公开策略仍是竞技场／年度结束即公开，PvE 只给本人；正式发布前如需延迟公开，另行配置。
- 旧 120 日存档、旧竞技场记录和旧回放需要迁移或只读兼容，不能用新日历和新规则静默重算。
